ORBIT VSEPR - VERSION 2 PROJECT WALKTHROUGH
==========================================

This document explains the Version 2 project in source order. Consecutive
statements that work together are explained as one block. Repeated HTML and
CSS tags are grouped by their purpose, while the program's behavior is
described step by step.


1. PROJECT OVERVIEW
-------------------

Orbit VSEPR is a web application for looking up molecules and displaying a
simple animated 3D model. A browser page sends a molecule name or PubChem CID
to a Flask server. The server looks for the molecule structure in the local molecule.dat
cache; otherwise it asks PubChem for the molecule's SMILES notation,
converts that notation to an atom-and-bond map, and updates the cache.
MySQL stores accounts and the history of molecules each signed-in user
rendered. A separate VPython process reads the structure from the cache,
creates the 3D objects, and animates them.

VSEPR means Valence Shell Electron Pair Repulsion. The project represents
atoms, bonds, and lone pairs. Its drawing is an educational visualization,
not a scientific molecular dynamics or geometry calculation package.

JSON API ROUTES
---------------

GET /api/session - api_session()
    Reads the shared username from session.txt, verifies that username against
    MySQL, and returns it as JSON. If the file is empty or the account no
    longer exists, it returns HTTP 401. File and database exceptions propagate.

GET /api/data - api_data()
    Returns JSON containing element details and molecule names. Element data
    and suggested names come from the reference CSV/text files; molecule names
    already saved in MySQL are added to the response. File and database errors
    propagate.

POST /api/login - api_login()
    Reads JSON from the request. Invalid JSON raises Flask's normal request
    error. It checks that the result is a dictionary, then reads the fields.

    The next condition requires a username of at least three characters, a
    password of at least six characters, and a class from 6 through 12.
    Invalid input returns JSON with HTTP 400.

    The route queries users in MySQL. A record is accepted only when username,
    plain-text password, and class all match. To keep Version 1's exact table
    structure, the plain-text password is stored in its existing password_hash
    column; no hashing is performed. On success, the username is written to
    session.txt. If no record matches, the route returns HTTP 401. Database
    exceptions are not caught.

POST /api/register - api_register()
    Reads and checks the same three fields as the login route. It inserts the
    checks for a duplicate username in users, then inserts the account. An
    existing username returns HTTP 409. Database exceptions are not caught.
    Otherwise it writes the username to session.txt and returns HTTP 200.

POST /api/logout - api_logout()
    Clears session.txt and returns a sign-out message with HTTP 200.

POST /api/molecule - api_molecule()
    Reads the request JSON. It first requires the body to be a dictionary,
    then requires identifier to be a non-empty string and strips whitespace.

    scene_width defaults to 960. The next check requires it to be an integer
    from 320 to 4096. It also explicitly rejects booleans because Python
    considers bool a subclass of int.

    After validating input, the route looks up the molecule, starts the viewer,
    and records the molecule name in user_molecules if a username is in
    session.txt. Repeated renders increment search_count and update
    last_searched. Lookup, network, process, and database exceptions are not
    caught and propagate to Flask.

carbon_map_from_smiles(smiles)
    This function parses SMILES text into the dictionary used by the viewer.
    SMILES is a compact notation for atoms, bonds, branches, and rings.

INITIAL STATE
    atoms stores each parsed atom and its bonds. branches remembers atoms at
    which a parenthesized branch began. rings remembers the first atom for a
    ring label until that label appears again. current_atom tracks the last
    atom. pending_bond stores a bond symbol until the next atom is added.
    index is the current position in the SMILES string.

INNER FUNCTION add_atom(symbol, aromatic=False, charge=0,
explicit_hydrogens=0)
    Checks that the element is present in the element table. It creates a new
    atom dictionary with its symbol, aromatic flag, charge, explicit hydrogen
    count, and initially empty bonds list. If there was a previous atom, it
    records the connection in both atoms. The bond order is the pending
    explicit order, or otherwise an aromatic order for two aromatic atoms
    and a single bond for other atoms. It then sets the new atom as current
    and clears the pending bond.

MAIN CHARACTER LOOP
    The while loop reads characters until the whole SMILES string has been
    consumed.

Bond characters -, =, #, :, /, and \
    Set pending_bond to single, double, triple, aromatic, or directional
    single bond order. The parser advances past the character and waits for
    the next atom or ring closure.

Opening parenthesis (
    Requires a current atom, saves it on branches, and continues. This is the
    point to which parsing returns after a side branch.

Closing parenthesis )
    Requires a saved branch point, restores that atom as current, and
    continues. Missing matching parentheses produce an invalid-SMILES error.

Dot .
    Sets current_atom to None so the next atom starts a separate connected
    component.

Ring digits and percent labels
    A digit is a one-character ring label. % must be followed by exactly two
    digits. On the first occurrence, the parser saves the current atom and any
    pending bond. On the second occurrence, it connects the saved atom to the
    current atom. If no bond order was specified, it chooses an aromatic
    connection when both atoms are aromatic, otherwise a single bond.

Bracket atom [...]
    Finds the closing bracket or raises an error. A regular expression reads
    the element symbol, including lower-case aromatic notation. The symbol is
    capitalized for lookup. Further expressions read an optional hydrogen
    count and charge. add_atom() then creates the atom.

Unbracketed atom
    The parser tries a two-character symbol for Cl or Br; otherwise it uses
    the current character. Lowercase symbols indicate aromatic atoms. The
    symbol is capitalized and checked against the element table before being
    added.

END-OF-PARSE VALIDATION
    Unclosed branches, unclosed ring labels, a trailing bond marker, or no
    atoms cause an invalid-SMILES error.

AROMATIC BOND ASSIGNMENT
    Aromatic bonds are given a consistent alternating single/double pattern.
    The sets track which atom pairs get double bonds and which atoms already
    took part in one. Nitrogen atoms with explicit hydrogens are excluded from
    this alternating assignment.

ATOM LABELS
    The code counts non-hydrogen atoms by element symbol and gives them labels
    such as C1, C2, and O1. Explicit hydrogen atoms are omitted here because
    the later valence logic labels attached hydrogens as they are processed.

VALENCE, HYDROGEN, AND LONE-PAIR CALCULATION
    For every non-hydrogen atom, the code totals its bond valence. Aromatic
    bonds use the chosen alternating assignment, except aromatic nitrogen
    bonds are counted as single for this calculation. Explicit hydrogens are
    added to the valence.

    Aromatic nitrogen has a special allowed-valence rule. Other atoms use the
    allowed valences from the element table, adjusted by the parsed charge.
    The first allowed valence at least as large as the current bond valence is
    selected. If none exists, the structure is rejected as unsupported.

    Missing implicit hydrogens are calculated from the difference between
    target valence and existing valence. The atom's attached_atoms list gets
    one entry per bond order, so a double bond repeats the neighbor twice.
    Existing explicit hydrogens and calculated implicit hydrogens are added
    with generated H labels.

    Lone-pair count is estimated from valence electrons, charge, and total
    valence. Each pair is added with a generated lp label. The completed
    attached_atoms list is stored in molecular_map under the atom's label.

    The function returns molecular_map, which is the atom connection map used
    by moleculeobj.py.

5. 3D MOLECULE CONSTRUCTION - vsepr/moleculeobj.py
-------------------------------------------------

IMPORTS
    The first import tries to load atom as part of the vsepr package; the
    fallback supports direct execution. Math functions and VPython shapes and
    vectors are used for placement and drawing.

class molecule
    Bundles atom objects, their connections, and the VPython shapes for one
    molecule.

molecule.__init__(struc)
    Creates one atom object for every unique label found among map keys and
    values. It extracts alphabetic characters from labels to determine the
    element/lone-pair symbol. It stores the labels, objects, and structure.
    Then it connects atoms, checks for a ring, chooses ring or chain
    positioning, and applies a small disturbance to start the animation.

attachatms()
    Walks through each central label and its neighbors. It connects the
    central atom to each neighbor and adds the reverse connection when the
    neighbor is not itself a key in the structure map.

hex_to_rgb(hex_color)
    Removes the leading #, converts each pair of hexadecimal digits into a
    number, and scales each red/green/blue component from 0..255 to 0..1 for
    VPython.

genstchain()
    Requests sphere creation with no preassigned central atom positions.

_bond_directions(atom_count)
    Returns no directions for zero attachments. Otherwise returns evenly
    spaced directions around a plane, one direction per attached atom.

_make_spheres(center_positions)
    Makes the real VPython spheres and attached-atom shapes. It first finds the
    center atoms and copies the supplied positions. A placement loop walks
    through already-positioned centers and positions any connected center
    atoms that do not yet have locations. Their positions are spaced using
    radii and directions based on the parent position.

    The next loop creates a sphere for every center atom and stores it on the
    atom object. The variable n is a fallback position counter used when a
    center has no calculated position.

    For each center, it builds a unique list of attached atoms and gets
    starting directions. Attached atoms that are not center atoms receive
    positions around their center. For ring atoms, non-lone-pair attachments
    are placed outward from the ring.

    Lone pairs are drawn as a translucent sphere shell with two smaller
    electron spheres, joined with VPython compound(). Other attached atoms are
    drawn as colored spheres. Each shape is stored on its atom object, and the
    center ball is mapped to the list of its attached shapes.

cylinders()
    Creates cylinders to depict bonds. It skips lone-pair connections and
    tracks sorted atom-label pairs so each bond is drawn only once. The number
    of parallel cylinders is based on how many times the neighbor appears in
    either direction of the structure map. This lets repeated neighbors draw
    double and triple bonds. The cylinder positions are updated later during
    rendering. The function returns the saved cylinder records.

checkcycle()
    Runs a depth-first search across bonds between center atoms. The path and
    visited set track the search. If it reaches an already visited atom other
    than its parent, and the cycle has at least three atoms, that portion of
    the path is saved as the ring. It then records whether a ring was found.

gencyclic()
    If no ring exists, falls back to genstchain(). Otherwise it calculates
    the distances needed between neighboring ring atoms. It estimates a
    circle radius by binary search so the angles subtended by those distances
    total one full circle. Each ring atom receives a position on that circle,
    and _make_spheres() positions the ring and its attachments.

disturb()
    For each center atom, gathers its non-center attachments and their bond
    vectors. It uses a cross product to find a normal to the plane of those
    vectors. If a normal exists, it nudges attached atoms slightly in
    alternating directions along that normal. This avoids starting with every
    group perfectly flat.


6. VPYTHON ANIMATION - vsepr/rendering.py
-----------------------------------------

IMPORTS AND CONSTANTS
    Imports the molecule builder and VPython vector, scene, color, and rate
    tools. DAMPING reduces velocity over time. MAX_PAIR_FORCE caps repulsion
    force, and MAX_ATOM_SPEED caps atom speed.

keep_bond_lengths(bonds)
    Repeats up to twelve times. For each bonded pair, it measures the distance
    and compares it with the sum of atom radii. It moves both atoms halfway
    toward correcting the distance error. If the distance is zero, it chooses
    a fallback direction. It stops early when the largest error is tiny.

bond_side(first, second)
    Finds a unit vector perpendicular to the bond direction. It normally uses
    the z-axis as a reference, switching to the y-axis when the bond is nearly
    parallel to z. This direction offsets parallel cylinders for multiple
    bonds.

render(mole, width=None, height=None, background=None)
    Sets any requested scene dimensions and a default gray background. It
    creates the molecule object and bond cylinders. It builds unique lists of
    real atom bonds and all geometry bonds, excluding lone-pair connections
    from the displayed chemical bonds.

    The infinite animation loop runs the following steps repeatedly:

    1. Reset the force on every atom.
    2. Compare each pair of atoms. If they are not bonded and their distance
       is nonzero, calculate a repulsion force and apply equal/opposite forces.
       MAX_PAIR_FORCE limits that force.
    3. For each atom with neighbors, calculate the part of its force that is
       perpendicular to each bond. Average the result across its unique
       neighbors, divide by mass to obtain acceleration, and update velocity.
    4. Apply damping and cap velocity at MAX_ATOM_SPEED.
    5. Move the atom using its velocity and the timestep dt.
    6. Call keep_bond_lengths() so bonds remain near their target lengths.
    7. Move each bond cylinder to the current atom positions and recompute its
       offset direction.
    8. Call VPython rate() so the display can update.

SCRIPT REFERENCES AND STATE
    The script finds the form and elements it will update. isRegistering
    starts false, so the page initially operates in sign-in mode.

setMode(registering)
    Stores the selected mode. It changes the title, explanatory text, submit
    label, password autocomplete value, button styling, and aria-pressed
    accessibility states. It also clears the old message and error styling.

Mode button handlers
    Clicking Sign in calls setMode(false); clicking Create account calls
    setMode(true).

Form submit handler
    Prevents a full-page form submission, shows a progress message, clears
    error styling, and disables the submit button. It sends a JSON POST to
    /api/login or /api/register depending on the selected mode. It reads the

    Success redirects to the home page. The catch block displays the error,

11. DATA AND DEPENDENCY FILES
-----------------------------

data/elements.csv
    A table with one row per element. Columns include atomic number, symbol,
    name, atomic mass, covalent radius, electronegativity, display color,
    valence-electron count, and allowed valences. element.py uses these values
    to build atom objects; nameProcessing.py uses valence data to estimate
    hydrogens and lone pairs.

data/molecule_names.txt
    A newline-separated list of suggested molecule names. main.py returns
    these names through /api/data.

data/molecule.dat
    The local binary pickle cache of molecule structures. It uses the same
    cache format as Version 1.

data/local/users.txt
    Version 2 does not use this file. Account records are stored in MySQL.

data/local/session.txt
    Stores the single shared signed-in username. This is the one account datum
    intentionally kept in a local text file; it is not a cookie or a separate
    session for each browser.

requirements.txt
    Lists the Python packages used by the project: Flask, the MySQL connector,
    PubChemPy, and VPython.

__pycache__ folders
    Contain Python-generated bytecode cache files. They are not source code
    and do not need to be explained or edited.


12. END-TO-END REQUEST FLOW
---------------------------

1. The user starts main.py.
2. main.py starts Flask on 127.0.0.1:5000 and opens the home page.
3. The user opens the VPython page and submits a molecule name or CID.
4. The browser sends the identifier to POST /api/molecule.
5. main.py checks molecule.dat. If there is no saved structure, it calls
   carbon_map() to query PubChem and parse the returned SMILES.
6. The structure map is saved to molecule.dat.
7. main.py launches vsepr/vpython_viewer.py as a separate process.
8. The viewer loads the structure from molecule.dat and calls rendering.render().
9. If a user is signed in, main.py records that user's render in
   user_molecules in MySQL.
10. moleculeobj.py creates and positions atoms, lone pairs, and bond shapes.
11. rendering.py repeatedly applies repulsion, movement, bond correction,
    and scene updates.


13. IMPORTANT PROJECT LIMITS
----------------------------

Accounts and rendered-molecule history are stored in MySQL. Passwords are
stored as readable plain text at the user's request. Anyone with database
access can read them; do not use real or reused passwords.

The sign-in state is one shared local text file, not browser-specific. Signing
in from one browser changes the local state seen by another. The app does not
use cookies.

The web server binds to 127.0.0.1 and is intended for use on the same computer.
MySQL Connector and a running MySQL server are required for app startup. The
element CSV, suggested-molecule text list, and molecule structure cache remain
local, matching Version 1.

The sign-in page and session API display account status, but the molecule
route still allows anonymous rendering. The molecule search-history table only
records a render when a username is signed in.

Version 1's users table already contains password hashes. Version 2 does not
hash passwords and compares the stored value directly. Existing hashed
Version 1 accounts therefore cannot sign in in this mode; the app explains
that a new username is needed. Their passwords cannot be recovered from the
stored hashes without using the hashing check that was explicitly removed.

The project path is hard-coded in main.py. If Version 2 is moved, update
BASE_DIR before starting the application.
